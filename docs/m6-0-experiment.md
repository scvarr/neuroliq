# Эксперимент M6.0: structural knowledge round-trip

Результат: минимальное отображение `OccurrenceId → ConceptId`, упорядоченные Route и их RouteBundle сохранили различия обеих ручных control-пар, потерянные при проекции только на ConceptId. Все четыре конструкции прошли JSON round-trip с совпадением канонических структур. Это ограниченный структурный результат, а не подтверждение восстановления смысла произвольного текста или принятие общей архитектуры знаний.

## Контракт и граница

Отдельный `src/neuroliq/m6_0.py` строит ручной Graph через существующий публичный API. UUID int=501..506 соответствуют HUMAN, HIT, TALL, PLAY, BASKETBALL, WELL. Пять нетипизированных неориентированных Connection: HUMAN—HIT, TALL—HUMAN, HUMAN—PLAY, PLAY—BASKETBALL, WELL—PLAY; все strength=1.0. Labels служат только сборке controls и диагностике; алгоритм читает непрозрачные ConceptId и тождество вхождений.

Experiment representation содержит только `occurrences` и `routes`. OccurrenceId — локальная непустая строка; каждое определённое вхождение должно использоваться, каждый используемый адрес должен быть определён. Bundle и Route непустые; одноэлементный Route допустим. ConceptId должен существовать в L0, каждая соседняя пара проекции должна иметь Connection. Проверка не достраивает путь. Соседние одинаковые ConceptId отклоняются, поскольку существующий Graph запрещает self-loop; повторение ConceptId через промежуточный концепт допустимо.

Последовательность эксперимента:

```text
ручная конструкция → RouteBundle → validate/project через Graph
→ JSON serialize → deserialize → повторная validate/project → canonical structure
```

Сравнение canonical сохраняет ConceptId, порядок внутри Route, кратность Route и тождество вхождений внутри и между маршрутами. Имена OccurrenceId, порядок записей отображения и порядок перечисления Route в bundle незначимы. Bundle трактуется как мультимножество Route. Канонизация перебирает порядок Route, переименовывает вхождения по первому появлению и выбирает лексикографический минимум. Это точная процедура для малых ручных controls; её факториальная сложность по числу Route не исследуется как масштабируемое решение.

Graph/Concept/Connection, Activation, существующая маршрутизация, ExperimentDefinition и Graph Lab не менялись. Представление и JSON — только экспериментальные данные, без production storage/API. Текст, LLM, БД, MCP, language layer, координаты знания, provenance/evidence/grounding, статистика, состояние сессии и обучение не входят в эксперимент.

## Фактический результат

| Проверка | Конструкция A | Конструкция B | Результат |
| --- | --- | --- | --- |
| Два HUMAN | `h1 → hit1 → h2` | `h1 → hit1 → h1` | Обе проекции `HUMAN → HIT → HUMAN`; canonical A содержит три вхождения, B — два |
| Якорь HUMAN | `t1 → h1`; `h1 → p1 → b1`; `w1 → p1` | `t1 → h1`; `h2 → p1 → b1`; `w1 → p1` | Проекции совпадают; A содержит пять вхождений и общий HUMAN, B — шесть и раздельные HUMAN |

В первом control canonical Route A — `o0 → o1 → o2`, B — `o0 → o1 → o0`; o0/o2 в A имеют один ConceptId HUMAN, но остаются разными вхождениями. Во втором control общий p1 остаётся якорем PLAY всех соответствующих Route обеих конструкций; общий h1 сохраняется только в A. Обе проекции bundle: `TALL → HUMAN`, `HUMAN → PLAY → BASKETBALL`, `WELL → PLAY`.

В каждом из четырёх round-trip `round_trip_equal=true` и `projection_preserved=true`; в обеих парах `same_projection=true` и `different_structure=true`. Отрицательная конструкция `TALL → BASKETBALL` отклонена: Connection отсутствует в L0.

Полный диагностический результат сохранён в `experiments/m6-0-structural-round-trip.json`: исходные вхождения и Route, ConceptId-проекции, сериализованные документы, исходная и восстановленная canonical structure, сравнения и причина отклонения. Концепты и все одинаковые strengths также видны в диагностике.

## Воспроизведение и validation

Из корня с установленными зависимостями проекта:

```text
python -m neuroliq.m6_0
python -m pytest tests/test_m6_0.py -q
git diff --check
```

12 targeted tests прошли: обе control-пары с независимыми эталонами проекций, разные и повторные вхождения HUMAN, общие якоря HUMAN/PLAY, JSON round-trip, переименование OccurrenceId и перестановка Route/отображения, значимость порядка внутри Route и кратности Route, другие непрозрачные ConceptId без labels, неизменность Graph и объектов Connection, отсутствующая Connection/Concept и запрещённый self-loop, некорректные конструкции, совпадение CLI с сохранённой диагностикой. `git diff --check` прошёл. Полный suite не запускался: изменения изолированы в новом эксперименте и его тестах, широкий regression cone не обнаружен.

## Ограниченный исследовательский вывод

Для заданных controls представление достаточно, чтобы сохранить раздельные вхождения одного смысла и общие структурные якоря, которые стирает ConceptId-проекция. Проверено структурное тождество с точностью до переименования, а не истинность содержания, языковые роли или восстановление текста. Эксперимент не подтверждает достаточность для произвольных знаний, извлечение, заполнение графа или критерий всего первого исследовательского цикла. Route/RouteBundle остаются рабочей гипотезой общей архитектуры; M6.0 реализует только её ограниченную проверку.
