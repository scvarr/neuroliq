# Эксперимент M3: структурное пересечение

Минимальная гипотеза: сочетание нескольких исходных активных концептов меняет ранжирование кандидатов за счёт структурного пересечения на неизменном графе с нетипизированными связями и одинаковыми persistent strength. Вычисления выполняет существующий `Activation` M2 без изменения формулы, pruning policy или введения маршрутизатора.

## Fixture и контроль

Файл `experiments/m3-simple-retrieval.neuroliq.json` через общий loader строит ровно пять концептов и четыре неориентированные связи:

```text
СТОЛИЦА -- ПАРИЖ
СТОЛИЦА -- ЛОНДОН
ФРАНЦИЯ -- ПАРИЖ
ФРАНЦИЯ -- ЛИОН
```

Все связи имеют `strength=1.0`, без типов отношений. Метки внешние и не участвуют в вычислениях. UUID фиксированы только для воспроизводимости; они не являются семантическими признаками:

| Метка | UUID |
| --- | --- |
| СТОЛИЦА | 00000000-0000-0000-0000-0000000000c9 |
| ФРАНЦИЯ | 00000000-0000-0000-0000-0000000000ca |
| ПАРИЖ | 00000000-0000-0000-0000-0000000000cb |
| ЛОНДОН | 00000000-0000-0000-0000-0000000000cc |
| ЛИОН | 00000000-0000-0000-0000-0000000000cd |

Во всех трёх запусках: `decay=0.5`, `max_active=5`, `max_steps=1`, activation каждого seed — `1.0`. На step 0 seeds сохраняются полностью; выполняется ровно один propagation. Лимит ширины не отсекает ни seeds, ни кандидатов: все `kept=true`, `pruned=[]` на обоих шагах. Retention отсутствует. Единственная изменяемая величина между запусками — состав seeds. Постоянные концепты, связи, соседство и strength остаются одинаковыми.

Вклад перехода — `source_activation * strength * decay = 1.0 * 1.0 * 0.5 = 0.5`. Activation кандидата — сумма его вкладов. Таблицы ниже передают полный вычислительный trace шага 1 с заменой UUID внешними метками. Полный JSON, включая step 0, доступен в Graph Lab через просмотр шага.

## Запуск 1: СТОЛИЦА

Step 0: `СТОЛИЦА=1.0`. Sources шага 1: только `СТОЛИЦА=1.0`.

| Source → target | source_activation | strength | decay | contribution |
| --- | ---: | ---: | ---: | ---: |
| СТОЛИЦА → ПАРИЖ | 1.0 | 1.0 | 0.5 | 0.5 |
| СТОЛИЦА → ЛОНДОН | 1.0 | 1.0 | 0.5 | 0.5 |

| Кандидат | Суммарная activation | kept |
| --- | ---: | --- |
| ПАРИЖ | 0.5 | true |
| ЛОНДОН | 0.5 | true |

Ничья. ПАРИЖ не является уникальным лидером. ФРАНЦИЯ и ЛИОН не входят в candidates этого шага.

## Запуск 2: ФРАНЦИЯ

Step 0: `ФРАНЦИЯ=1.0`. Sources шага 1: только `ФРАНЦИЯ=1.0`.

| Source → target | source_activation | strength | decay | contribution |
| --- | ---: | ---: | ---: | ---: |
| ФРАНЦИЯ → ПАРИЖ | 1.0 | 1.0 | 0.5 | 0.5 |
| ФРАНЦИЯ → ЛИОН | 1.0 | 1.0 | 0.5 | 0.5 |

| Кандидат | Суммарная activation | kept |
| --- | ---: | --- |
| ПАРИЖ | 0.5 | true |
| ЛИОН | 0.5 | true |

Ничья. ПАРИЖ не является уникальным лидером. СТОЛИЦА и ЛОНДОН не входят в candidates этого шага.

## Запуск 3: СТОЛИЦА + ФРАНЦИЯ

Step 0: `СТОЛИЦА=1.0`, `ФРАНЦИЯ=1.0`. Sources шага 1: оба seeds с activation `1.0`.

| Source → target | source_activation | strength | decay | contribution |
| --- | ---: | ---: | ---: | ---: |
| СТОЛИЦА → ПАРИЖ | 1.0 | 1.0 | 0.5 | 0.5 |
| СТОЛИЦА → ЛОНДОН | 1.0 | 1.0 | 0.5 | 0.5 |
| ФРАНЦИЯ → ПАРИЖ | 1.0 | 1.0 | 0.5 | 0.5 |
| ФРАНЦИЯ → ЛИОН | 1.0 | 1.0 | 0.5 | 0.5 |

| Кандидат | Aggregation | Суммарная activation | kept |
| --- | --- | ---: | --- |
| ПАРИЖ | 0.5 от СТОЛИЦА + 0.5 от ФРАНЦИЯ | 1.0 | true |
| ЛОНДОН | 0.5 от СТОЛИЦА | 0.5 | true |
| ЛИОН | 0.5 от ФРАНЦИЯ | 0.5 | true |

ПАРИЖ становится уникальным лидером: `1.0 > 0.5`. Лидерство полностью объясняется aggregation двух переходов в общий соседний концепт. Ни повышенного веса, ни дополнительного seed ПАРИЖ, ни скрытого источника activation нет. Равные значения сортируются по UUID; положение первым при ничьей в одиночных запусках не считается уникальным лидерством.

## Воспроизведение и проверка

```text
docker compose up --build
```

Открыть [Graph Lab](http://127.0.0.1:17890), загрузить `experiments/m3-simple-retrieval.neuroliq.json` и нажать «Выполнить». Файл содержит совместные seeds; для одиночных сценариев отключайте второй или первый seed и повторяйте запуск. Параметры остаются прежними. «Просмотр шага» показывает ranking, contributions и исходный JSON trace каждого шага. Подробный формат, управление портом и команды проверки: [Graph Lab](graph-lab.md). Остановка — `docker compose down`.

Тесты `tests/test_m3.py` читают обычный experiment-файл и проверяют все три сценария через общий loader и web API, точную структуру, равные strength, полные contributions, отсутствие pruning, неизменность core-графа, детерминизм и независимость от меток и порядка создания структуры/seeds. Исследовательские результаты ниже не изменены при инструментальном переносе M4.1.

## Исследовательский вывод

Подтверждена ограниченная гипотеза M3 на этом контролируемом fixture: комбинация исходных концептов меняет относительное ранжирование соседних кандидатов через структурное пересечение при фиксированных одинаковых weights. Вычислительный путь наблюдаем и объясняется имеющимся baseline M2.

Не подтверждены понимание «столицы Франции», семантика отношений, универсальная маршрутизация, сложное извлечение, память контекста, обучение или перенос на другие графы. Граф искусственный, и общий сосед выбран при конструировании fixture; алгоритм лишь агрегирует числовые вклады по заданной топологии. Замена меток произвольными именами оставила бы результат тем же. Увеличение общей seed activation с 1.0 до 2.0 увеличивает суммарный сигнал, но само по себе не объясняет лидерство: лишь ПАРИЖ получает два равных вклада, остальные — один.

Это частичная проверка критерия первого исследовательского цикла из `foundation.md`: показаны изменение ранжирования при смене активного состояния и объяснимость пути на фиксированном графе. Общий механизм выбора маршрутов, сложные промежуточные структуры, объективное сравнение маршрутизаторов и существенно меньший рабочий подграф на большом графе здесь не проверялись. Поэтому весь первый цикл не объявляется успешным. Roadmap и архитектурные гипотезы не расширяются.
