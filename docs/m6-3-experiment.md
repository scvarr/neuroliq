# M6.3: структурное сходство surface-узлов на русском корпусе

Реальный bounded-прогон выполнен 7 октября 2026 года: ровно 500 000 token occurrences, 76 948 surface-узлов и 295 508 неориентированных связей. Частичный структурный сигнал наблюдается, но две проверенные меры не дают надёжного поиска известных словоформных семейств. Это проверка сигнала в surface graph, не факторизация и не semantic L0.

## Ограниченный механизм

`src/neuroliq/m6_3.py` переиспользует `RawTextBaseline.ingest_document` и точный tokenizer M6.2 без изменений. Graph core и strength=1.0 не менялись. Profile содержит ConceptId, множество непосредственных соседей, их накопленные частоты наблюдений пары, частоту самого узла и degree. Self-pair остаётся в диагностическом счётчике M6.2, но не создаёт координату профиля, поскольку в Graph нет self-loop. Между документами связей нет.

- Jaccard: `|N(a) ∩ N(b)| / |N(a) ∪ N(b)|`.
- Cosine: `Σ_n count(a,n) × count(b,n) / sqrt(Σ_n count(a,n)^2 × Σ_n count(b,n)^2)`. Координаты — соседние ConceptId; вес — сырая накопленная целочисленная частота неориентированной пары M6.2, включая оба порядка наблюдения. Никакой нормализации весов, кроме деления на нормы в cosine, нет.
- Пустой union или нулевая норма дают score=0. Частота query и degree показываются в диагностике, но не становятся дополнительными коэффициентами score.
- Все другие surface-узлы участвуют в ranking, включая кандидатов с нулевым overlap. Query исключён. Порядок: score descending, затем token key ascending по Unicode, без UUID.
- Numeric scores вычисляются только из ConceptId/целочисленных счётчиков. Labels используются для lookup query, разрешения точных ничьих и отображения готового ranking. Переименование labels может переставить равные scores, но не меняет сами scores.

Нет строковых признаков, edit distance, stemming, морфологии, внешних словарей, embeddings, TF-IDF, learned weights, LLM, 2-hop, left/right-направлений, merge/split, факторизации, semantic rewriting, БД или production ingestion. Контрольные формы находятся только во внешнем файле диагностики и не зашиты в алгоритм.

## Источник и воспроизводимость

Источник: [deepvk/cultura_ru_edu_llama3_annotations](https://huggingface.co/datasets/deepvk/cultura_ru_edu_llama3_annotations), фиксированный split `validation`, revision `1082c2c8ac044d5fe1a9a27cb942e98ba7fa3110`, shard `data/validation-00000-of-00001.parquet` (16 614 870 байт). Исходный порядок строк и только колонка `text`; остальные поля не участвуют. Адаптер `m6_3_dataset.py` отделён от core и similarity, скачивает фиксированный shard во временный файл и читает parquet batches только с `text`. Дополнительная зависимость pyarrow нужна только сетевому исследовательскому запуску; подставной iterable source не импортирует её и не обращается к сети.

Окружение фактического запуска: Python 3.13.2, Unicode database 15.1.0, pyarrow 23.0.1. Корпус не фильтровался по языку, пунктуации, редкости или качеству текста. Token occurrences включают punctuation по контракту M6.2.

Остановка происходит на yield checkpoint существующего генератора M6.2 точно после входящего соседства N-го токена; остаток последнего документа и последующие документы не обрабатываются. Сам последний документ NFC-нормализуется целиком, как в M6.2. Snapshots независимы; отчёт сохраняет численные scores без округления. При раннем исчерпании источника API выдаёт final с фактическим меньшим размером, не объявляя достижение лимита.

```powershell
$env:PYTHONUTF8='1'
python -m pip install -e ".[research,test]"
python -m neuroliq.m6_3 --dataset --queries experiments/m6-3-queries.json --top-n 10 > experiments/m6-3-corpus-results.jsonl
```

Для локальных документов: `--files document1.txt document2.txt` вместо `--dataset`; доступны `--limit`, `--checkpoints`, `--top-n`. Queries JSON имеет формат `{"студент": ["студенты", "студентов", "вода"]}`. Ключ вводится уже в identity M6.2; не выполняется скрытая лемматизация или исправление query. API: `StructuralAnalysis(baseline).token_ids[key]` возвращает соответствующий ConceptId, `profiles[id]` — профиль, `rank(id, "jaccard"/"cosine", top_n)` — численный ranking по ID, `diagnose(key, controls=..., top_n=...)` — вывод с labels. UUID не выводятся в корпусный JSON, чтобы диагностика была воспроизводимой.

Полный фактический вывод всех 18 запрошенных ключей на всех checkpoints, включая top-10, top соседей и raw numeric scores: [m6-3-corpus-results.jsonl](../experiments/m6-3-corpus-results.jsonl). Конфигурация queries: [m6-3-queries.json](../experiments/m6-3-queries.json).

## Исследовательский результат и ограничения

Есть отдельные положительные находки: `школы → школе` и обратное направление имеют Jaccard rank=1 на 500k (score=0.174419); ранее `школы → школе` было 27 на 100k и 4 на 250k. Cosine для `школа → школы`: 52 → 4 → 6 (score на 500k=0.397550). Это пример сигнала непосредственно наблюдаемого соседства; он не доказывает существование или восстановление скрытого компонента.

Для семейства человек сигнал остаётся недостаточно селективным: `человек → люди` по Jaccard улучшился 3682 → 321 → 188, но ни одна из этих форм не вошла в top-10 друг друга на 500k. Cosine score для этой пары высок (0.860132), но rank=415; похожее распределение частых соседств есть у множества посторонних форм.

Большинство известных родственных форм не попало в top-10. У `программист ↔ программистов` обе метрики дают ноль. Редкие формы имеют частоты 1–4 и мало соседей: общие punctuation/служебные соседи создают множество точных ничьих, в том числе с числовыми и латинскими surface-токенами. У `студент` cosine top-10 состоит из посторонних редких ключей; отрицательные `вода`, `книга`, `музыка` получают scores выше родственных форм. Частые соседи и веса доступны в отчёте, поэтому эти эффекты наблюдаемы.

Рост корпуса не гарантирует улучшения ranks: `школа → школе` cosine ухудшился 4013 → 12956 → 13827; `студенты → студентов` cosine 1644 → 538 → 1035. Меняется и сам профиль, и число кандидатов. Нулевые scores на ранних размерах нельзя интерпретировать через абсолютный rank.

Таким образом, surface graph содержит некоторый структурный сигнал, достаточный для отдельных удачных кандидатов, но этого эксперимента недостаточно для утверждения надёжного поиска общей скрытой структуры. Контроли вручную заданы и не являются полной разметкой: это ограниченная диагностика, без общей метрики качества, significance или отдельной проверки всех top-кандидатов. Неравномерные частоты, punctuation, служебные слова, шум исходного текста и множество редких узлов ограничивают результат. Дополнительные эвристики намеренно не добавлялись. Факторизация, построение semantic L0, межъязыковая универсальность и изменение архитектуры не подтверждены.
