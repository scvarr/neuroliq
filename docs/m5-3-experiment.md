# Эксперимент M5.3: краткоживущее направленное состояние

Результат: минимальное локальное transient state изменило следующий выбор маршрута на искусственной цепочке, затем старое состояние продолжило затухать к нейтрали. Control выбрал A → B → A → B; dynamic выбрал A → B → C → D. Все числа trace совпали с заданными эталонами без допуска: это точно представимые двоичные дроби.

## Контракт и граница

Топология A—B—C—D загружается из `experiments/m5-3-transient-direction-state.neuroliq.json` существующим ExperimentDefinition. UUID int=401..404 соответствуют A..D; persistent strengths A—B=1.0, B—C=0.75, C—D=1.0. Оба сценария используют один и тот же объект Graph, seed A=1.0, decay=0.5, max_active=1, max_steps=3.

Отдельный пакетный эксперимент `src/neuroliq/m5_3.py` только читает публичный API Graph. Activation M2 используется для валидации и step 0; его propagation не изменён. Эксперимент ограничен одним seed и одним выбранным переходом на шаге. При ничьей используется UUID. Предыдущая activation заменяется activation выбранного candidate.

Временное отображение `r[(source, target)]` существует отдельно для обоих направлений каждой Connection, initial/neutral=0. Параметры фиксированы: h=0.5, rho=0.5. Формулы:

```text
g_ij = 1 - r_ij
contribution = source_activation * connection.strength * g_ij * decay
```

Сначала все candidates рассчитываются по текущему r, затем выбирается один максимальный. Только после фактически выбранного i→j в dynamic выполняются последовательно:

```text
для всех существующих направлений: r = rho * r
r[j, i] = h
```

Расчёт и отбрасывание candidates не меняют r. Пройденное направление не усиливается. Control использует ту же формулу при постоянно нулевом r, без update. Отсутствующий переход не вызывает update.

Graph, Connection, Activation M2, ExperimentDefinition и Graph Lab не менялись. Новые DB, session runtime, LLM, language layer, learning, visited/history/provenance, routing framework и production storage не добавлены. Диагностические traces сохраняются только как результат; выбор читает текущую activation, постоянное соседство/strength и текущий r, а не предыдущие traces или список пройденных концептов.

## Фактический trace

На step 0 candidate/kept A=1.0, sources/transitions пусты, все r=0. В таблице строки transitions идут по UUID target; kept обозначает фактический выбор. Candidates равны contributions, поскольку источник один. При ранжировании kept идёт первым, остальные candidates отбрасываются.

| --- | ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Control | 1 | A→B | 1.0 | 1.0 | 0 | 1.0 | 0.5 | 0.5 | да |
| Control | 2 | B→A | 0.5 | 1.0 | 0 | 1.0 | 0.5 | 0.25 | да |
| Control | 2 | B→C | 0.5 | 0.75 | 0 | 1.0 | 0.5 | 0.1875 | нет |
| Control | 3 | A→B | 0.25 | 1.0 | 0 | 1.0 | 0.5 | 0.125 | да |
| Dynamic | 1 | A→B | 1.0 | 1.0 | 0 | 1.0 | 0.5 | 0.5 | да |
| Dynamic | 2 | B→A | 0.5 | 1.0 | 0.5 | 0.5 | 0.5 | 0.125 | нет |
| Dynamic | 2 | B→C | 0.5 | 0.75 | 0 | 1.0 | 0.5 | 0.1875 | да |
| Dynamic | 3 | C→B | 0.1875 | 0.75 | 0.5 | 0.5 | 0.5 | 0.03515625 | нет |
| Dynamic | 3 | C→D | 0.1875 | 1.0 | 0 | 1.0 | 0.5 | 0.09375 | да |

| Шаг | Control после update | Dynamic после update (ненулевые значения) |
| ---: | --- | --- |
| 0 | все r=0 | все r=0 |
| 1 | все r=0 | r_BA=0.5 |
| 2 | все r=0 | r_BA=0.25, r_CB=0.5 |
| 3 | все r=0 | r_BA=0.125, r_CB=0.25, r_DC=0.5 |

В dynamic A→B, B→C, C→D остаются с r=0 на всех выполненных шагах. Отброшенные B→A и C→B не устанавливают refractory значения для A→B и B→C. Старое r_BA затухает при последующих выбранных переходах, без проверки посещённых узлов. При отсутствии повторной установки рекурсия даёт r_BA=0.5×0.5^k → 0 и g_BA → 1; проверены первые три ненулевых значения. Точное достижение нуля за конечное число шагов, течение физического времени и затухание без переходов не исследуются.

## Воспроизведение и validation

Из корня с установленными зависимостями проекта:

```text
python -m neuroliq.m5_3
python -m pytest tests/test_m5_1.py tests/test_m5_2.py tests/test_m5_3.py -q
git diff --check
```

CLI выводит полный JSON с labels, UUID, параметрами, sources, transitions (strength/r/g/contribution/kept), ранжированными candidates, kept/pruned и всеми шестью значениями transient_after_update каждого шага обоих сценариев. Сохранён фактический диагностический запуск: `experiments/m5-3-trace.json`; targeted test сверяет его с новым CLI-запуском. Топология переносима обычным experiment-файлом, однако Graph Lab по-прежнему исполняет M2; dynamic M5.3 воспроизводится отдельной командой.

Проверка: 11 targeted tests прошли, включая 5 M5.3 и 6 M5.1/M5.2. Проверены полные точные численные traces обоих сценариев, совпадение control с M2, различие маршрутов, последовательность 0.5→0.25→0.125, отсутствие воздействия отброшенных candidates, отсутствие усиления пройденных направлений, повторяемость, сохранённый CLI-output, неизменность концептов/связей/соседства/strength и идентичность объектов Connection при чтении в обоих направлениях. Несколько seeds/choices отклоняются. `git diff --check` прошёл. Полный suite не запускался: core, loader и web не менялись.

## Ограниченный исследовательский вывод

Подтверждено только, что минимальное локальное transient directional state может заменить некоторую явную историю недавнего прохождения для данного искусственного выбора и затем затухать. Оно изменило выбор B→A на B→C без изменения постоянного Graph. Это не подтверждает полноценную модель контекста сессии и не доказывает, что refractory-механизм является будущей архитектурой Neuroliq.

Эксперимент не проверяет длительную интерактивную сессию, новые входящие концепты между ответами, общее предотвращение циклов/эха, долговременную устойчивость, достаточность состояния для реальных маршрутов, несколько активных источников, подбор h/rho или масштабирование. Повторные установки могут препятствовать затуханию конкретного направления. Рабочие гипотезы остаются гипотезами; roadmap и критерий всего первого исследовательского цикла не изменены.
