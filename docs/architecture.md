# Архитектура

Постоянная структура M1 и отдельное временное состояние M2 реализованы в памяти на Python 3.11+. Серверного постоянного хранилища нет; переносимый JSON эксперимента введён в M4.1.

## Модель и ограничения M1

`src/neuroliq/graph.py` содержит:

- `ConceptId` — UUID, трактуемый как непрозрачный идентификатор;
- `Concept` — неизменяемая запись только с полем `id`;
- `Connection` — неизменяемая запись с полями `concept_a`, `concept_b`, `strength`;
- `Graph` — контейнер концептов, связей и симметричного индекса соседства в памяти.

Метки, семантические типы рёбер и состояние активации отсутствуют в модели. `strength` принимает `int` или `float` и хранится как конечный Python `float`; `bool`, NaN, ±inf и числа, не представимые конечным `float`, отклоняются. Семантика и предметный диапазон силы не определены.

Граф технически неориентированный в M1. Пара UUID служит каноническим ключом связи; перестановка концов не создаёт другую связь. Самосвязи и повторное создание связи запрещены. Оба конца должны существовать в графе. Это не фиксирует фундаментальное решение об ориентированности проекта.

## Минимальный API

| Метод | Результат и ошибки |
| --- | --- |
| `create_concept(concept_id=None)` | Новый `Concept`; по умолчанию UUID4. Явный UUID допустим для воспроизводимых графов; повторный ID в этом графе вызывает `ValueError`. |
| `get_concept(concept_id)` | `Concept` или `None`, если его нет. |
| `create_connection(a, b, strength)` | Новая `Connection`; self-loop, дубликат или неконечная сила вызывают `ValueError`, неверный тип — `TypeError`, отсутствующий конец — `KeyError`. |
| `get_connection(a, b)` | Одна и та же связь для обоих порядков концов; `None`, если связи нет. |
| `neighbors(concept_id)` | Кортеж соседних ConceptId; неизвестный концепт вызывает `KeyError`. |
| `concepts()` / `connections()` | Кортежи неизменяемых записей. |

Перечисление и соседство сохраняют порядок создания. Возвращаемые кортежи являются снимками коллекций; последующие добавления их не меняют. Отклонённая операция не меняет структуру графа. API изменения силы или удаления структуры в M1 отсутствует.

## Fixture и диагностика

`src/neuroliq/fixture.py` строит искусственную структуру с фиксированными UUID: пять концептов, включая изолированный, и четыре связи. Человеческие метки возвращаются отдельным словарём `ConceptId → str`; их значения не определяют структуру или смысл связей.

`diagnostic_snapshot(graph, labels=None)` в `src/neuroliq/diagnostics.py` возвращает текст с концептами, концами связей и силами. Концепты и связи сортируются по UUID, поэтому одинаковая структура с одинаковыми ID и метками имеет одинаковый snapshot независимо от порядка добавления. Метки экранируются как JSON-строки, силы выводятся через `repr(float)`. Автоматически созданные UUID случайны; воспроизводимость между независимыми построениями fixture обеспечивают его явные фиксированные ID.

Диагностика читает минимальный API и не меняет граф. Диагностика постоянной структуры не зависит от runtime M2. Маршрутизация, поиск ответа, языковой слой, MCP и LLM не реализованы.

## Временная активация M2

`src/neuroliq/activation.py` содержит отдельный `Activation`, читающий публичный API Graph. Поля `Concept` и `Connection` не изменены. `start(seeds, decay=..., max_steps=..., max_active=...)` валидирует запуск до замены состояния. Seeds — отображение существующих UUID в конечные неотрицательные числа; decay — конечное число от 0 до 1, max_steps — целое >= 0, max_active — целое >= 1. Отрицательные strength отклоняются при старте M2, их семантика не исследуется; Graph по-прежнему допускает их.

Step 0 ранжирует явно заданные seeds и применяет тот же лимит max_active; candidates содержат исходные значения, transitions и sources пусты. Для последующих шагов каждый source в порядке UUID передаёт каждому соседу в порядке UUID вклад `source_activation * connection.strength * decay`. Contributions в один target суммируются в этом фиксированном порядке. Предыдущая activation не сохраняется. Из candidates выбираются первые max_active по убыванию суммы и возрастанию UUID при равенстве. Нулевые значения сохраняются как candidates и участвуют в том же ранжировании; отдельного порога активности нет. Неориентированность позволяет волне возвращаться по связи.

`step()` выполняет один переход; после max_steps состояние не меняется. `run()` выполняет оставшиеся переходы до лимита, включая пустые шаги. `reset()` уничтожает activation, параметры и trace. `snapshot()` возвращает независимую копию текущего состояния и всей истории. Каждый trace содержит номер шага, sources с activation, transitions с source/target, source_activation, strength, decay и contribution, ранжированные candidates с суммой и флагом kept, списки kept/pruned. Переполнение contribution или суммы отклоняет текущий шаг без изменения состояния; уже завершённые шаги run остаются доступными.

Baseline не считается правильной моделью Neuroliq: он проверяет наблюдаемость волны, aggregation и ограничение ширины/глубины. Он не извлекает ответ, не маршрутизирует и не реализует память контекста. Структура Graph в рамках запуска считается фиксированной; runtime сам не пишет в неё.

## Graph Lab и ExperimentDefinition (M4.1)

`src/neuroliq/experiment.py` определяет отдельное переносимое описание: UUID и внешние labels концептов, нетипизированные связи и strength, seeds и параметры запуска. Definition не является Graph и не содержит runtime/trace. `build()` создаёт новый Graph через существующий API и отдельное отображение labels. Формат и правила валидации описаны в [Graph Lab](graph-lab.md).

`src/neuroliq/web.py` предоставляет единственный `app`, по умолчанию с пустым экспериментом. `create_app(definition=None)` создаёт независимый экземпляр стенда. `GET /api/experiment` возвращает definition, `GET /api/experiment/export` — JSON для сохранения. `PUT /api/experiment` валидирует целый документ и строит новую структуру до замены текущего состояния; при ошибке возвращает 422 и сохраняет прежний эксперимент/runtime. При успешной замене, включая метки и параметры, создаёт новый Graph, labels и пустой Activation. Старый trace больше недоступен. Mutating API в Graph не добавлен.

`GET /api/graph` читает публичный API текущего графа и возвращает concepts с id, label, neighbors и connections с концами/strength. `GET /api/activation` возвращает snapshot. `POST /api/activation/start` запускает step 0 из `definition.run`; `/step` и `/run` автоматически начинают запуск, если runtime пуст, затем выполняют переход или оставшиеся переходы; `/reset` очищает runtime, сохраняя definition. Повторный шаг после лимита ничего не меняет. Ошибки Activation возвращают 422, неизвестная команда — 404.

Один runtime и definition общие для вкладок одного процесса; команды и чтение сериализуются блокировкой. Сохранение документа заменяет состояние целиком: при одновременном редактировании последняя успешная запись побеждает. Сервер не хранит experiment-файлы: экспорт/импорт выполняются пользователем. Перезапуск начинает пустой эксперимент.

Статический frontend и локальный Cytoscape.js входят в Python-пакет. Экран редактирует definition, создаёт UUID4 новых концептов, позволяет менять labels, удалять концепты вместе с связями этого концепта и seeds, добавлять/редактировать/удалять связи, выбирать seeds и параметры. Изменения применяются после выхода из поля; очередь команд в одной вкладке сохраняет порядок записи и запуска. Невалидное изменение показывает ошибку; текущий подтверждённый документ остаётся прежним. JSON можно импортировать файлом или из поля; экспорт загружает текущий подтверждённый документ. Масштаб и позиции узлов относятся только к представлению.

JavaScript отображает текущую activation, ranking, contributions и полный trace выбранного шага из Python snapshot. Формула, aggregation и pruning находятся только в неизменном `Activation`. Метки не участвуют в вычислениях, ничья не трактуется как уникальное лидерство.

## Воспроизводимые M3/M4

`experiments/m3-simple-retrieval.neuroliq.json` хранит прежние фиксированные UUID, пять меток и четыре связи strength=1.0; decay=0.5, max_active=5, max_steps=1. Совместные seeds СТОЛИЦА/ФРАНЦИЯ дают ПАРИЖ=1.0 против 0.5; одиночные дают ничьи 0.5. См. [M3](m3-experiment.md).

`experiments/m4-two-step-bridge.neuroliq.json` хранит A—C—X—D—B, C—E, D—F с прежними UUID, семью концептами и шестью strength=1.0; decay=0.5, max_active=7, max_steps=2. Совместные A/B дают X=0.5 против остальных 0.25; одиночные — ничьи 0.25. Возвраты C→A/D→B сохранены. См. [M4](m4-experiment.md).

Оба файла загружаются общим loader и Graph Lab; отдельные M3/M4 builders и web-app удалены. M1/M2 fixtures остаются для core-тестов и диагностики. M4.1 — инструментальная подготовка к M5; roadmap M0–M8 и исследовательские выводы не изменены.
