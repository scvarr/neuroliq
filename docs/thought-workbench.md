# Ручной Thought Workbench

Отдельная страница `/thought-workbench` открывается по ссылке из Graph Lab, lexical review и постоянного L0. Запуск существующего приложения: `python -m uvicorn neuroliq.web:app --host 127.0.0.1 --port 8000`. Workbench использует ту же локальную SQLite: по умолчанию `data/lexical-workspace.sqlite3`, другой файл задаётся `NEUROLIQ_WORKSPACE_DB`. Для persistence после restart запускайте приложение с тем же путём БД.

## Ручная процедура

1. В каталоге нажмите «Новый концепт», введите человеческую подсказку и сохраните. UUID создаётся независимо от текста; одинаковые подсказки не объединяются автоматически. Можно создать первые 50–100 концептов, искать по подсказке/ID и редактировать выбранную запись.
2. Создайте исходный фрагмент, вставьте текст и необязательный context. Сохраните фрагмент. Никакой tokenizer или автоматическое создание концептов не запускается.
3. Создайте мысль, выберите сохранённый источник, задайте подсказку мысли и сохраните. Один фрагмент может использоваться несколькими мыслями.
4. В «Локальном элементе» выберите reusable concept из каталога и задайте локальную подсказку. Поиск каталога фильтрует также список выбора. Сохраните элемент. Для нового участия того же понятия нажмите «Новый элемент» и выберите тот же концепт: получится другой локальный UUID.
5. Для literal выберите вид «Literal / текстовое значение» и введите значение. Любые числа, имена, JSON или другой текст здесь сохраняются как строка без интерпретации.
6. Выберите «Откуда» и «Куда», добавьте стрелку. Несколько стрелок из одного элемента образуют ветвление. Направления не меняют Graph/L0; типов связей нет.
7. Клик по узлу или выбор в списке открывает элемент для редактирования. Удаление элемента удаляет его связи; клик по стрелке или выбор в списке позволяет удалить связь. Изменения подтверждайте кнопками сохранения, прежде чем переключать записи или выполнять другую операцию.
8. Выбирайте сохранённые мысли для продолжения работы. Источник редактируется отдельно и обновляется во всех использующих его мыслях. Мысль удаляется вместе с её локальной конструкцией; источник остаётся. Используемый концепт или источник удалить нельзя, пока ссылки не убраны.

Граф показывает внешние annotations и literals; сокращённые локальные ID помогают различать одинаковые участия. Полные ID видны в редакторе и JSON. Сохранённое состояние переживает рестарт, раскладка узлов строится заново.

## Передача на внешний review

«Экспорт полного JSON» скачивает весь Workbench. Файл содержит версию формата, полный каталог annotations, исходные тексты/context, мысли с source_id, локальные элементы с concept_id или value, локальные annotations и directed links. Передайте этот файл в новый ChatGPT-сеанс вместе с исследовательским вопросом; скрытого состояния для чтения конструкции не требуется. Человеческие annotations не определяют вычислительную семантику ID и не доказывают выразительность языка.

Для импорта выберите полный snapshot и нажмите «Импортировать snapshot». Это заменяет весь Workbench; перед заменой сохраните нужный экспорт. Graph Lab, L0 и lexical workspace не заменяются. Сервер валидирует целый документ до записи; ошибка оставляет прежнее состояние. Экспорт каноничен: одинаковые ID, записи и направления дают одинаковые байты независимо от порядка добавления. Export → import → export сохраняет канонический JSON точно.

Контракт хранения и API описан в [architecture.md](architecture.md#persistent-manual-thought-workbench). Это bounded-инструмент для локальной работы: literals текстовые, массивы не кодируют порядок аргументов, layout не сохраняется, совместное редактирование одной мысли разрешается последней записью. Формальная грамматика, semantic edge types, layer architecture, language adapter и reasoning/runtime не определены.
