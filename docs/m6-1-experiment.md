# Эксперимент M6.1: временное достраивание неполной структуры

Результат: ограниченный структурный поиск нашёл две временные кандидатные достройки между WALK и FALL. Неизменная Activation M2 за один propagation step дала им равную поддержку 1.0; CLUE_ICE сделал P2 уникальным лидером с 1.5, CLUE_ROAD зеркально сделал P1 лидером с 1.5. L0 и исходный RouteBundle остались неизменными. Это проверка на искусственном симметричном графе, не общая архитектура достраивания знаний.

## Исходная структура и граница

Отдельный `src/neuroliq/m6_1.py` использует публичные Graph/Activation API и экспериментальный RouteBundle M6.0. Graph, Connection, формула Activation M2 и M6.0 не изменены. UUID int=601..609 соответствуют HUMAN, WALK, FALL, ROAD, ASPHALT, ICE, SLIP, CLUE_ROAD, CLUE_ICE. Все десять Connection нетипизированные, неориентированные, strength=1.0:

```text
WALK — ROAD — ASPHALT — FALL
WALK — ICE  — SLIP    — FALL
HUMAN — WALK; HUMAN — FALL
CLUE_ROAD — ROAD; CLUE_ICE — ICE
```

Сохранено только `h1 → HUMAN`, `w1 → WALK`, `f1 → FALL` и два ordered Route: `h1 → w1`, `h1 → f1`. Их ConceptId-проекции — `HUMAN → WALK`, `HUMAN → FALL`. ROAD, ASPHALT, ICE и SLIP существуют в L0, но не получают OccurrenceId и не добавляются в RouteBundle.

Кандидатный путь — только временная последовательность ConceptId. Это не saved Route, не новое постоянное знание и не изменение L0. Стрелки ниже обозначают порядок перечисления пути, без семантического типа рёбер. CLI выводит диагностический JSON; механизм не сохраняет достройки в файл или структуру знаний.

LLM, MCP, БД, language layer, provenance/evidence, координаты знания, route statistics, обучение, длительное состояние сессии и M5.3 transient directional state отсутствуют. Каждый сценарий создаёт свежую Activation на тех же объектах Graph и RouteBundle; это сравнение уточнений, а не продолжение живущей сессии.

## Поиск и локальная метрика

Общий DFS перечисляет простые пути без повторения ConceptId. Ограничения fixture: максимум три ребра и 100 раскрытых состояний пути. Исчерпание бюджета раскрытий вызывает ошибку, а не выдачу неполного набора как полного. Граница длины определяет исследуемый набор, а не утверждение об отсутствии более длинных путей в произвольном графе.

Все явно сохранённые ConceptId запрещены как внутренние узлы; концы допускаются. Поэтому WALK → HUMAN → FALL исключён общим правилом, независимо от labels. Найдены ровно:

```text
P1: WALK → ROAD → ASPHALT → FALL
P2: WALK → ICE → SLIP → FALL
```

Seeds — множество ConceptId всех сохранённых вхождений с activation=1.0. Уточнение добавляет один ConceptId с activation=1.0; число вхождений одного концепта не усиливает seed. Параметры: decay=0.5, max_steps=1, max_active=9 (все концепты); pruning отсутствует.

Локальная диагностическая метрика:

```text
candidate_support(path) = сумма activation внутренних ConceptId после шага 1
```

Она не является степенью истинности или evidence. Поиск читает только топологию, затем M2 независимо распространяет seeds по всему данному L0; метрика оценивает найденные пути. Нет специальных правил для labels или конкретных UUID. UUID задают только порядок перечисления при ничьей; первый в ничьей не объявляется уникальным лидером.

Адаптер не нужен: M2 заменяет активное состояние на очередную волну, но каждый из двух внутренних узлов каждой ветви смежен с одним из seeds WALK/FALL. Поэтому буквально один шаг активирует оба внутренних узла. Это свойство данной трёхрёберной топологии; для более длинных путей одного шага может быть недостаточно.

## Полное численное объяснение

Шаг 0 baseline: HUMAN=WALK=FALL=1.0. В уточнённых сценариях дополнительно CLUE_ICE=1.0 либо CLUE_ROAD=1.0. Каждый вклад шага 1 равен `source_activation × strength × decay = 1.0 × 1.0 × 0.5 = 0.5`.

Все transitions baseline и обоих уточнённых сценариев:

| Source | Target | Contribution |
| --- | --- | ---: |
| HUMAN | WALK | 0.5 |
| HUMAN | FALL | 0.5 |
| WALK | HUMAN | 0.5 |
| WALK | ROAD | 0.5 |
| WALK | ICE | 0.5 |
| FALL | HUMAN | 0.5 |
| FALL | ASPHALT | 0.5 |
| FALL | SLIP | 0.5 |

В сценарии CLUE_ICE ровно один дополнительный transition: CLUE_ICE → ICE с contribution=0.5; в сценарии CLUE_ROAD — CLUE_ROAD → ROAD с contribution=0.5. Других transitions шага 1 нет. Уточнения не доходят до SLIP/ASPHALT за этот шаг: новые активации не распространяются внутри того же шага.

Во всех сценариях HUMAN=1.0 (два вклада), WALK=FALL=0.5. Оба CLUE отсутствуют в активном состоянии шага 1 (значение при чтении по умолчанию 0). Внутренние узлы и ranking:

| Сценарий | ROAD | ASPHALT | ICE | SLIP | P1 support | P2 support | Лидер |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| baseline | 0.5 | 0.5 | 0.5 | 0.5 | 1.0 | 1.0 | Ничья |
| CLUE_ICE | 0.5 | 0.5 | 1.0 | 0.5 | 1.0 | 1.5 | Только P2 |
| CLUE_ROAD | 1.0 | 0.5 | 0.5 | 0.5 | 1.5 | 1.0 | Только P1 |

Полный CLI JSON отдельно показывает saved occurrences/routes, их ConceptId-проекции, candidate paths, внешние labels, bounds/exclusions поиска, seeds, параметры и оба trace M2, sources/transitions со всеми множителями, candidates/kept/pruned, activation, внутренние значения, support, ranking и множество лидеров. Там же доступны Graph до/после (все concepts, connections/strength, соседство), RouteBundle до/после и его точные сериализации. После каждого сценария проверяются равенство Graph, структуры bundle и UTF-8 bytes его сериализации; все три флага true. Проверка неизменности не полагается на `frozen` модели: вложенные dict/list RouteBundle сами по себе допускают мутацию.

## Воспроизведение и validation

Из корня с установленными зависимостями:

```text
python -m neuroliq.m6_1
python -m pytest tests/test_m6_1.py tests/test_m6_0.py -q
git diff --check
```

На Windows перед этими командами в cmd.exe: `set PYTHONUTF8=1`; эквивалент в PowerShell: `$env:PYTHONUTF8='1'`. Системный CP1251 у subprocess CLI M6.0 иначе несовместим с чтением JSON bytes как UTF-8 в существующем тесте; M6.0 ради окружения не менялся.

19 targeted tests прошли: 7 M6.1 и 12 M6.0. Новые проверки непосредственно подтверждают два пути, исключение HUMAN общим правилом, отсутствие циклов, границы длины/раскрытий, точные seeds, активации, support и лидеров, полный набор contributions и восстановление всей activation из них, отсутствие pruning, отдельность candidate concepts от OccurrenceId, неизменность bytes/структуры bundle, Graph и объектов Concept/Connection. Пересборка с произвольными UUID, обратным порядком создания и переименованными OccurrenceId без передачи labels сохраняет результаты с точностью до отображения UUID. CLI соответствует вычисленной диагностике. `git diff --check` прошёл. Полный suite не запускался: core и M6.0 не менялись, широкий regression cone отсутствует.

## Ограниченный вывод

На данном fixture неполная occurrence-структура задаёт seeds и границу явно заданного, неизменный L0 предоставляет два структурных кандидата, а дополнительный концепт меняет их относительную поддержку через обычную агрегацию M2. Обе достройки остаются временными даже после появления уникального лидера. Не проверены истинность объяснения падения, достраивание произвольных знаний, достаточность метрики на других длинах/топологиях, масштабируемость поиска или общая архитектура completion engine. Roadmap M0–M8 и критерий всего первого исследовательского цикла не расширены.
