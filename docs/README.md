# Навигатор документации Neuroliq

Этот документ — канонический корень навигации по проектной документации. Дерево `docs/` содержит текущее состояние проекта, описание реализации, исследовательские принципы и гипотезы, результаты экспериментов, решения и инструкции по инструментам. Навигатор помогает выбрать документы для конкретной задачи, не заменяет их содержание и не принимает архитектурных или исследовательских решений.

Файлы сгруппированы по назначению без переноса или переименования. Ниже перечислены все существующие Markdown-документы дерева, включая `decisions/`. При добавлении нового документа включайте ссылку на него в соответствующую группу. Правила работы агентов находятся также в корневом [AGENTS.md](../AGENTS.md); общее знакомство с проектом и запуск — в корневом [README.md](../README.md).

## Карта документов и их роли

- [README.md](README.md) — этот навигатор: карта дерева и выбор маршрута чтения.

### Реализованная архитектура (implemented architecture)

- [architecture.md](architecture.md) — описание реально реализованного устройства: графовое ядро M1, временная активация M2, ExperimentDefinition и Graph Lab, с краткой картой изолированных bounded-модулей M5/M6. Этот документ должен описывать реализацию; исследовательские предложения сами по себе не становятся её частью.

### Исследовательская основа (foundation) и терминология

### Рабочие исследовательские гипотезы

Эта группа содержит непроверенные модели и обсуждение ограниченных проверок. Это выбор исследовательского фокуса, не формальная иерархия истинности; статус и границы читаются в самих документах.

## Как читать различия и конфликты

Назначения документов различаются, поэтому навигатор не задаёт общую формальную иерархию приоритетов.

- `current-state.md` сообщает, что актуально сейчас, и помогает выбрать релевантный контекст. Упоминание текущей гипотезы не означает, что она реализована.
- `architecture.md` должен описывать реализованное устройство. Hypothesis-документ описывает исследуемую модель, а не реализованную архитектуру.
- Experiment-документ фиксирует исторический результат при конкретных условиях и ограничениях. Его не следует переписывать только потому, что позднее изменилась модель; новый результат оформляется отдельно.
- ADR читается вместе с его явным статусом и границами. Исследовательский принцип, гипотеза, принятое решение и факт реализации — разные виды утверждений.
- `chatgpt.md` регулирует workflow ChatGPT и не разрешает архитектурные вопросы проекта.

Различие назначения, времени или экспериментальных условий само по себе не означает противоречия. Если обнаружено реальное противоречие между утверждениями документов, навигатор не должен молча выбирать содержательную истину. Такое место — кандидат для отдельного documentation audit: нужно обозначить конкретные утверждения и их контекст, а содержательное разрешение вынести в отдельную ограниченную задачу. Этот навигатор не выполняет такой аудит и не исправляет содержание источников.
