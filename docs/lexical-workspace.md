# Лексическое ревью L0 bootstrap

Первый локальный русский lexical workspace реализует батч → кандидатные семьи → проверка одной семьи → принять / отклонить / разделить / показать ещё → результат с основаниями. Принятие сохраняет reviewed-сопоставление вхождений с непрозрачным `mapping_id`. Это вспомогательный surface adapter: Решения ревью не меняют ConceptId. При загрузке батча независимо от ревью строится постоянный нефакторизованный L0; грамматические категории, факторы и типы рёбер не создаются.

## Запуск и процедура

Запустить `docker compose up --build`, открыть [лексическое ревью](http://127.0.0.1:17890/lexical). Ссылка есть в шапке Graph Lab. Compose сохраняет SQLite в `./data` на хосте: перезапуск и пересоздание контейнера сохраняют батчи. Прямой запуск:

```powershell
python -m pip install -e ".[web,research,test]"
python -m uvicorn neuroliq.web:app --host 127.0.0.1 --port 17890
```

По умолчанию БД — `data/lexical-workspace.sqlite3` относительно рабочего каталога; путь переопределяется переменной `NEUROLIQ_WORKSPACE_DB`. Локальные данные не входят в Git.

1. Создать батч из фиксированного реального корпуса [M6.3](m6-3-experiment.md) либо локальных `.txt` в строгом UTF-8. Корпус использует прежние dataset, revision, split и shard; скачивается заново для каждого батча, требует сети и pyarrow. Каждый новый dataset-батч продолжает сохранённый row/token ordinal; граница внутри документа поддерживается без повторной обработки начала. При исчерпании корпуса API возвращает 422 без изменения курсора и БД. Файлы идут по имени; файл/строка корпуса — отдельный документ.
2. Указать лимит вхождений, включая пунктуацию. 10 000 — экспериментальный default. API этого стенда ограничивает запрос 100 000 вхождений; локальный ввод — 200 документов, 2 млн символов на документ и 10 млн на батч. Это ограничения синхронного стенда, не константы архитектуры L0.
3. Выбрать семью, рассмотреть формы, частоты, строковое основание и выделенные вхождения. «Открыть источник» показывает весь NFC-документ, позицию, ссылку, hash исходного UTF-8 и число обработанных токенов. Остаток последнего документа сохранён, но не входит в обработанные occurrences.
4. «Показать ещё 8 примеров» расширяет выборку в фиксированном порядке; объём раскрытия сохраняется сервером.
5. Указать проверяющего; свободный комментарий необязателен для принятия, отклонения и разделения. Принять/отклонить применяется ко всем текущим вхождениям семьи, включая нераскрытые. В очереди ожидающих открывается следующая семья; в режиме «Все семьи» выбранная остаётся для аудита.
6. Для разделения отметить целые формы или конкретные примеры. Объединение выбранного переносится в новую ожидающую семью; обе части должны быть непустыми. Обе ожидающие части можно разделять дальше, включая одинаковую форму по контексту.
7. Фильтры дают доступ к принятым/отклонённым семьям. История и источники доступны после решения. Экспорт JSON версии 1 содержит полный батч и массовые mappings. Импорт экспорта пока отсутствует; рабочее состояние восстанавливается из SQLite.

## Генератор и свидетельства

`lexical_workspace.py` переиспользует tokenizer M6.2 (NFC/casefold, тот же учёт пунктуации). Исторические M6.2/M6.3 не изменены. `ru-surface-prefix-v1` берёт полностью русские формы `[а-яё]{4,}` с частотой ≥2. Многоформная семья имеет общий префикс ≥4 символов и остаток каждой формы ≤3 символов. Префиксы рассматриваются по убыванию длины, затем по Unicode; уже использованные формы исключаются. Транзитивного объединения нет. Остальные повторные формы образуют отдельные одноформные гипотезы. Семьи приоритизированы по числу форм, числу вхождений и строковому списку форм. ID исходной семьи детерминирован по её формам; батч, ручная дочерняя семья и принятое сопоставление получают UUID.

Это строковое основание, не морфология или поиск скрытого компонента. Возможны ложные сближения вроде `день/деньги`; одинаковая форма автоматически не разделяется по смыслу. Сходство M6.3 не стало автоматической истиной: исторический эксперимент показал слабую селективность соседств. Нет ML, LLM или скрытого классификатора.

Начальная выборка — восемь примеров. Порядок: первые представители каждой формы, затем ещё не покрытых документов, затем редких точных окружений (24 символа слева/справа), с ничьёй по номеру вхождения. Каждый член входит в порядок ровно один раз. «Редкое окружение — проверить» — слабый диагностический сигнал, часто почти все контексты уникальны. Карточка содержит до 160 символов с каждой стороны; полный источник доступен отдельно. Очередь и свидетельства имеют ограниченную высоту, единица работы — семья.

## Хранение и API

SQLite хранит атомарный JSON-снимок батча, отдельно от Graph Lab runtime. Сохраняются исходный текст и NFC-представление, SHA-256 исходного UTF-8 и ссылка документа; ordinal/смещения всех обработанных токенов, включая негруппированные; версия/параметры генератора и версия Unicode; состав, статус, родитель семьи и объём раскрытия. Это основания для будущей повторной интерпретации; алгоритм разрушительной L0-репроекции здесь отсутствует. В той же БД сохраняются один L0, внешний словарь и corpus cursor; создание батча атомарно сохраняет snapshot, проекцию и продвижение корпуса.

Provenance действия автоматически сохраняет время UTC, обязательного проверяющего, ревизию, полный состав до действия и список раскрытых примеров независимо от наличия комментария. Необязательное поле `note` сохраняется как передано; отсутствие поля в API означает пустую строку. Список раскрытых примеров означает доступные свидетельства, а не подтверждение прочтения человеком. Разделение добавляет ID дочерней семьи и точный список перенесённых occurrences. Наблюдения не удаляются. Принятие даёт `family_id → mapping_id + occurrence_ids` только для этого батча; это не универсальное правило будущих текстов и не ConceptId L0.

| API | Назначение |
| --- | --- |
| `GET /api/lexical`, `POST /api/lexical` | Батчи; создание из `local` или `dataset`, default limit 10 000. |
| `GET /api/lexical/{id}` | Параметры, диагностика, очередь, объём принятых mappings. |
| `GET /api/lexical/{id}/families/{family}` | Семья, раскрытые примеры и история. |
| `POST /api/lexical/{id}/families/{family}` | Обязательные `revision`, `action`, `reviewer`; необязательные `note`, `selected` (occurrence IDs) и `forms`. |
| `GET /api/lexical/{id}/sources/{source}` | Полный документ и provenance. |
| `GET /api/lexical/{id}/export` | Все observations, история и mappings. |
| `GET /api/l0` | Размеры L0/словаря и сохранённые corpus cursors. |
| `GET /api/l0/dictionary?q=...&limit=50` | Поиск по началу NFC/casefold-формы; максимум 200, явное усечение. |
| `GET /api/l0/concepts/{ConceptId}?limit=50` | Локальный индуцированный подграф: центр и до 200 прямых соседей, полная степень, отдельные подписи из словаря. |

Неверные типы/неизвестные поля отклоняются; отсутствующие ссылки дают 404, неверное действие/разделение — 422. `BEGIN IMMEDIATE` сериализует решения; устаревшая ревизия даёт 409 без изменения данных. Решённые семьи нельзя повторно принимать/отклонять или разделять, но можно раскрывать дополнительные примеры. Имя проверяющего вводится пользователем и не аутентифицируется.

## Проверка и ограничения

Ручной браузерный smoke 7 октября 2026: создать реальный validation-батч 10 000; получено 736 семей, 2 980 сгруппированных и 7 020 негруппированных observations. Найти `школ`, открыть `школ/школа/школы` (15 вхождений), раскрыть 8 → 15, открыть полный row=9 с подсветкой и hash; выделить форму `школ` (3), принять оставшиеся `школа/школы` (12), отклонить дочернюю семью. Остановить/заново запустить uvicorn, перезагрузить страницу: решения, массовые сопоставления, раскрытие и история сохранены. Это тест процесса, не научное подтверждение семейств.

Дополнительно в браузере: найти `день/деньги`, выделить только occurrence #6170 в названии «День М», разделить 7 → 6 + 1, проверить сохранение остальных вхождений `день` в исходной семье и отклонить её ложное строковое сближение. В режиме аудита выбранная семья остаётся открытой после решения. Скачать экспорт и открыть источник уже принятой семьи после рестарта. Проверены узкая компоновка и широкий экран 1280×1000.

Контекст позволил увидеть обычные школы, музыкальное образование, переведённый школьный текст и повтор заголовка. Есть ложные строковые сближения; большинство наблюдений остаётся вне групп. Одноформных семей много, очередь длинная, хотя отдельные вхождения не требуют решений. На узком экране очередь над карточкой требует дополнительной прокрутки. Создание батча синхронное, без прогресса по документам и отмены; каждый запрос читает снимок, каждое решение переписывает его. Масштабируемость за пределами локального стенда не доказана. Нет пересмотра/отмены решений, переноса review-решений между батчами, факторизации, семантических меток, маршрутов или динамики.

Релевантные lexical-тесты проверяют: tokenizer/позиции и источники, детерминированность и границы группировки, состав свидетельств, массовые mappings, разделение форм/occurrences, атомарный отказ, сохранение/рестарт, устаревшие ревизии, API-валидация и соседние Web/M6/package-контракты. Для accept/reject/split проверены отсутствие/пустота `note`, сохранение непустого комментария и автоматического provenance после рестарта, а также отклонение пустого reviewer без изменения данных. Полный suite не запускался: вычислительные механизмы M1/M2/M5/M6 не изменены.

```text
python -m pytest tests/test_persistent_l0.py tests/test_lexical_workspace.py tests/test_web.py tests/test_m6_2.py tests/test_m6_3.py tests/test_package.py -q
git diff --check
```

## Постоянный L0 и просмотрщик

Открыть [L0](http://127.0.0.1:17890/l0) из шапки ревью. Размеры показывают число ConceptId, структурных связей и форм общего внешнего словаря. Поиск по началу формы выдаёт `surface → ConceptId`; выбор открывает локальное соседство. Можно ввести UUID непосредственно, увеличить лимит соседей до 200 или перейти к другому узлу кликом. Полная степень и усечение показаны рядом с подграфом. Строки подписей читаются из внешнего словаря и не являются содержимым L0.

Каждая форма нового батча получает текущий ConceptId сразу при обработке, в том числе вне кандидатных семей. В карточке семьи рядом с известной формой доступен переход `ConceptId / L0`. Workspace `mapping_id` остаётся отдельным reviewed-сопоставлением occurrences. Принятие, отклонение и разделение семей не факторизуют и не объединяют ConceptId.

Курсор фиксированного корпуса виден в `/l0`; сведения о начале/конце конкретного dataset-батча доступны в summary/export (`corpus`). Локальные файлы не продвигают этот курсор. Старые review-снимки до введения постоянного L0 не репроецируются автоматически; первая последовательная dataset-загрузка начинает новый постоянный bootstrap. Исходные observations остаются сохранёнными.

Проверка milestone: 105 targeted-тестов — persistence/переиспользование ID, отсутствие duplicate/self connections и связей между документами, продолжение внутри документа с точными Unicode-смещениями, restart, атомарный rollback, сериализация параллельных батчей, API-переход lexical → ConceptId → подграф, независимость accept/reject/split и прежние lexical/web/M6/package-проверки. Браузерный smoke на отдельной тестовой БД: словарь, выбор ConceptId и локальный подграф из трёх узлов/двух связей. Реальный сетевой dataset в этом milestone повторно не скачивался; continuation проверен на подставном потоке документов через тот же API.
