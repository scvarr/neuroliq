# Лексическое ревью L0 bootstrap

Первый локальный русский lexical workspace реализует батч → кандидатные семьи → проверка одной семьи → принять / отклонить / разделить / показать ещё → результат с основаниями. Принятие сохраняет reviewed-сопоставление вхождений с непрозрачным `mapping_id`. Это вспомогательный surface adapter: Graph, грамматические категории, факторы и типы рёбер не создаются.

## Запуск и процедура

Запустить `docker compose up --build`, открыть [лексическое ревью](http://127.0.0.1:17890/lexical). Ссылка есть в шапке Graph Lab. Compose сохраняет SQLite в `./data` на хосте: перезапуск и пересоздание контейнера сохраняют батчи. Прямой запуск:

```powershell
python -m pip install -e ".[web,research,test]"
python -m uvicorn neuroliq.web:app --host 127.0.0.1 --port 17890
```

По умолчанию БД — `data/lexical-workspace.sqlite3` относительно рабочего каталога; путь переопределяется переменной `NEUROLIQ_WORKSPACE_DB`. Локальные данные не входят в Git.

1. Создать батч из фиксированного реального корпуса [M6.3](m6-3-experiment.md) либо локальных `.txt` в строгом UTF-8. Корпус использует прежние dataset, revision, split и shard; скачивается заново для каждого батча, требует сети и pyarrow. Файлы идут по имени; файл/строка корпуса — отдельный документ.
2. Указать лимит вхождений, включая пунктуацию. 10 000 — экспериментальный default. API этого стенда ограничивает запрос 100 000 вхождений; локальный ввод — 200 документов, 2 млн символов на документ и 10 млн на батч. Это ограничения синхронного стенда, не константы архитектуры L0.
3. Выбрать семью, рассмотреть формы, частоты, строковое основание и выделенные вхождения. «Открыть источник» показывает весь NFC-документ, позицию, ссылку, hash исходного UTF-8 и число обработанных токенов. Остаток последнего документа сохранён, но не входит в обработанные occurrences.
4. «Показать ещё 8 примеров» расширяет выборку в фиксированном порядке; объём раскрытия сохраняется сервером.
5. Указать проверяющего и основание. Принять/отклонить применяется ко всем текущим вхождениям семьи, включая нераскрытые. В очереди ожидающих открывается следующая семья; в режиме «Все семьи» выбранная остаётся для аудита.
6. Для разделения отметить целые формы или конкретные примеры. Объединение выбранного переносится в новую ожидающую семью; обе части должны быть непустыми. Обе ожидающие части можно разделять дальше, включая одинаковую форму по контексту.
7. Фильтры дают доступ к принятым/отклонённым семьям. История и источники доступны после решения. Экспорт JSON версии 1 содержит полный батч и массовые mappings. Импорт экспорта пока отсутствует; рабочее состояние восстанавливается из SQLite.

## Генератор и свидетельства

`lexical_workspace.py` переиспользует tokenizer M6.2 (NFC/casefold, тот же учёт пунктуации). Исторические M6.2/M6.3 не изменены. `ru-surface-prefix-v1` берёт полностью русские формы `[а-яё]{4,}` с частотой ≥2. Многоформная семья имеет общий префикс ≥4 символов и остаток каждой формы ≤3 символов. Префиксы рассматриваются по убыванию длины, затем по Unicode; уже использованные формы исключаются. Транзитивного объединения нет. Остальные повторные формы образуют отдельные одноформные гипотезы. Семьи приоритизированы по числу форм, числу вхождений и строковому списку форм. ID исходной семьи детерминирован по её формам; батч, ручная дочерняя семья и принятое сопоставление получают UUID.

Это строковое основание, не морфология или поиск скрытого компонента. Возможны ложные сближения вроде `день/деньги`; одинаковая форма автоматически не разделяется по смыслу. Сходство M6.3 не стало автоматической истиной: исторический эксперимент показал слабую селективность соседств. Нет ML, LLM или скрытого классификатора.

Начальная выборка — восемь примеров. Порядок: первые представители каждой формы, затем ещё не покрытых документов, затем редких точных окружений (24 символа слева/справа), с ничьёй по номеру вхождения. Каждый член входит в порядок ровно один раз. «Редкое окружение — проверить» — слабый диагностический сигнал, часто почти все контексты уникальны. Карточка содержит до 160 символов с каждой стороны; полный источник доступен отдельно. Очередь и свидетельства имеют ограниченную высоту, единица работы — семья.

## Хранение и API

SQLite хранит атомарный JSON-снимок батча, отдельно от Graph Lab runtime. Сохраняются исходный текст и NFC-представление, SHA-256 исходного UTF-8 и ссылка документа; ordinal/смещения всех обработанных токенов, включая негруппированные; версия/параметры генератора и версия Unicode; состав, статус, родитель семьи и объём раскрытия. Это основания для будущей повторной интерпретации; алгоритм разрушительной L0-репроекции здесь отсутствует.

Действие содержит время UTC, проверяющего, основание, ревизию, полный состав до действия и список раскрытых примеров. Последний означает доступные свидетельства, а не подтверждение прочтения человеком. Разделение добавляет ID дочерней семьи и точный список перенесённых occurrences. Наблюдения не удаляются. Принятие даёт `family_id → mapping_id + occurrence_ids` только для этого батча; это не универсальное правило будущих текстов и не ConceptId L0.

| API | Назначение |
| --- | --- |
| `GET /api/lexical`, `POST /api/lexical` | Батчи; создание из `local` или `dataset`, default limit 10 000. |
| `GET /api/lexical/{id}` | Параметры, диагностика, очередь, объём принятых mappings. |
| `GET /api/lexical/{id}/families/{family}` | Семья, раскрытые примеры и история. |
| `POST /api/lexical/{id}/families/{family}` | `revision`, `action`, `reviewer`, `note`, необязательные `selected` (occurrence IDs) и `forms`. |
| `GET /api/lexical/{id}/sources/{source}` | Полный документ и provenance. |
| `GET /api/lexical/{id}/export` | Все observations, история и mappings. |

Неверные типы/неизвестные поля отклоняются; отсутствующие ссылки дают 404, неверное действие/разделение — 422. `BEGIN IMMEDIATE` сериализует решения; устаревшая ревизия даёт 409 без изменения данных. Решённые семьи нельзя повторно принимать/отклонять или разделять, но можно раскрывать дополнительные примеры. Имя проверяющего вводится пользователем и не аутентифицируется.

## Проверка и ограничения

Ручной браузерный smoke 7 октября 2026: создать реальный validation-батч 10 000; получено 736 семей, 2 980 сгруппированных и 7 020 негруппированных observations. Найти `школ`, открыть `школ/школа/школы` (15 вхождений), раскрыть 8 → 15, открыть полный row=9 с подсветкой и hash; выделить форму `школ` (3), принять оставшиеся `школа/школы` (12), отклонить дочернюю семью. Остановить/заново запустить uvicorn, перезагрузить страницу: решения, массовые сопоставления, раскрытие и история сохранены. Это тест процесса, не научное подтверждение семейств.

Дополнительно в браузере: найти `день/деньги`, выделить только occurrence #6170 в названии «День М», разделить 7 → 6 + 1, проверить сохранение остальных вхождений `день` в исходной семье и отклонить её ложное строковое сближение. В режиме аудита выбранная семья остаётся открытой после решения. Скачать экспорт и открыть источник уже принятой семьи после рестарта. Проверены узкая компоновка и широкий экран 1280×1000.

Контекст позволил увидеть обычные школы, музыкальное образование, переведённый школьный текст и повтор заголовка. Есть ложные строковые сближения; большинство наблюдений остаётся вне групп. Одноформных семей много, очередь длинная, хотя отдельные вхождения не требуют решений. На узком экране очередь над карточкой требует дополнительной прокрутки. Создание батча синхронное, без прогресса по документам и отмены; каждый запрос читает снимок, каждое решение переписывает его. Масштабируемость за пределами локального стенда не доказана. Нет пересмотра/отмены решений, переноса между батчами, факторизации, семантических меток, маршрутов или динамики.

81 целевой тест прошёл: tokenizer/позиции и источники, детерминированность и границы группировки, состав свидетельств, массовые mappings, разделение форм/occurrences, атомарный отказ, сохранение/рестарт, устаревшие ревизии, API-валидация и соседние Web/M6/package-контракты. Полный suite не запускался: вычислительные механизмы M1/M2/M5/M6 не изменены.
